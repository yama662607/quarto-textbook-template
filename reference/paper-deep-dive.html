論文精読教科書のつくり方

研究論文を読者が理解できる教科書に変える編集ガイド

論文精読教科書のつくり方（編集ガイド）

1 本の研究論文を、読者が本当に理解できる精読教科書に作り替えるための編集方法論。 「Quarto でどう書くか（機能）」ではなく、「何を・どういう方針で書くか（編集判断）」をまとめる。

  • 機能の書き方 → 機能対応表（Quarto 機能 → live demo 対応表）
  • ブラウザ内 Python → Quarto Live レシピ（Pyodide レシピ）
  • 取り込み・規約・禁止事項 → AGENTS.md
  • この文書 → 論文を教科書に変える編集の型と工程

実証: この方法論は本テンプレートから起こした AI-Descartes 精読教科書 （Nature Communications 論文を全 14 章に精読、CC BY 4.0）で運用し、有効性を確認したもの。 以下の例はそこから採っている。

0. この教科書が目指すもの（＝大事なことの核）

論文そのものは、査読・紙面・作法の制約で「行間」を大量に飛ばして書かれている。 精読教科書の価値は、論文が割けなかったコストを肩代わりして行間を埋めることにある。 だから章を書くたびに、次の 6 原則に照らす。

# 原則 一言でいうと なぜ効くか
1 忠実さ 核心は原文引用＋忠実訳で固定 読者が「訳者の解釈」と「原著の主張」を切り分けられる。信頼の錨
2 行間補完 論文が省いた定義・動機・導出を足す ここが教科書の本体。付加価値の 8 割
3 通し具体例 1 つの例を全章で使い回す 抽象概念が毎回「あの例でいうと」で着地する
4 誠実な限界 できない事・仮定・その後の発展を明示 過大評価を防ぎ、Q&A と次に読む論文へつながる
5 意味のある対話 手を動かすと理解が進む所だけ live 化 飾りの demo は逆に読者の集中を削る
6 検証可能性 図・式・数値・コードを原著と突き合わせる 教科書の誤りは原著の誤解として伝播する。最優先

アンチパターン: 逐語訳をただ並べる／引用で紙面を埋める／全部を live demo にする／ 「限界」章を省く／図を低解像度のまま貼る。いずれも「読めるが分からない」教科書になる。

1. 章の解剖（実証済みの型）

AI-Descartes 教科書の各章はほぼ同じ骨格でできている。この型をコピーして中身を差し替える。

## 節タイトル {#sec-xxx}

::: {.callout-note collapse="true"}
## 原文（抜粋, English）

> "核心となる 1〜3 文だけを原文で引用する。" — Author et al. YEAR [@bibkey]

:::

### 忠実な日本語訳

（上の引用に対応する自然な日本語訳。記号・式・固有名詞は原形のまま。
逐語ではなく、意味を落とさず日本語として読める訳にする。）

![図1 | キャプション（出典: Author et al. YEAR, Fig. 1, CC BY 4.0 [@bibkey]）](../assets/images/fig1.png){#fig-xxx}

### 詳細授業：なぜこれが必要なのか {#sec-xxx-why}

::: {.callout-tip}
## 直観：〜

（数式に入る前に、日常語で「何をやりたいのか」を 3〜5 行で。）
:::

#### 登場する対象を整理する

| 記号 | 名称 | 何か | 図での表現 |
| --- | --- | --- | --- |
| $f$  | 発見モデル | … | 灰色の多様体 |

::: {#def-xxx}
**定義（〜）.** （論文が暗黙に使っている定義を明示的に書き下す。）
$$ \beta(f)=0 \iff f \text{ is derivable from } B $$ {#eq-xxx}
:::

（「なぜ」「どこで効くか」を、前後の章への相互参照 @sec-… / @fig-… / @eq-… で張る。）

型のねらい

  • 原文は「畳む」（collapse="true"）。読者は普段は訳を読み、疑ったときだけ原文を開ける。 引用は核心 1〜3 文まで。段落ごと引用しない（それは翻訳であって精読ではない）。
  • 図には必ず出典（出典: … , CC BY 4.0 [@bibkey]）。ライセンスの尊重かつ信頼の担保。 図のキャプション自体も、原文引用＋忠実訳で二重化すると誤読が消える。
  • 詳細授業が本体。①直観 callout → ②記号の対応表 → ③明示的な定義（{#def-}）→ ④式（{#eq-} で番号）→ ⑤前後章への相互参照、の順で「行間」を埋める。
  • 相互参照（@sec- @fig- @eq- @tbl-）を多めに張ると、本全体が 1 枚の地図になる。

テンプレの出発点: 数式・定理中心の章は V-S-V レッスンテンプレート（V-S-V）、 PDF を訳しながら起こす章は PDF textbook テンプレート（Phase 1/2）を cp して書き始める。

2. 制作の工程（論文 → 教科書）

Phase 0 — 準備（取り込み）

  1. just extract-pdf <pdf> <start> <end> で画像化 + text/OCR/LaTeX 抽出。
  2. 出力 PNG を 1 ページずつ Read で視認（AGENTS.md の必須手順）。 text と LaTeX だけでは図表配置・式番号・OCR 誤読を必ず取りこぼす。
  3. 図は高解像度でクロップして quarto/assets/images/ に置く（低解像度のまま貼らない）。 出典行に元 Fig 番号と CC ライセンスを記録しておく。

Phase 1 — 構造を決めきる（章割り）

執筆前に、全章の構成を確定する。 ここを詰めきると各章は独立に書ける。

  • 論文の構造に沿って章立てする（Abstract / Intro / Results / Discussion / Methods / 付録）。 読者が原論文と往復できる。AI-Descartes 教科書の例:

    部 章 対応
    第 I 部 導入と全体像 00 全体像・01 Abstract・02 Introduction 論文の入口
    第 II 部 枠組み 03 問題設定・04 距離(ε/β)・05 統合・06 相互作用・07 検証 Results
    第 III 部 考察 08 Discussion Discussion
    第 IV 部 事例研究 09 Kepler・10 時間の遅れ・11 Langmuir・12 限界 Methods
    第 V 部 付録 13 付録 難所の隔離先

  • 通し具体例を 1 つ選ぶ（AI-Descartes では Kepler の第三法則）。抽象概念を導入するたびに、 この例で必ず着地させる。全章で使い回す。

  • 難所は付録へ隔離する。完全性・Gödel・重い証明など、本筋を止める話題は本編から追い出し、 付録に 1 節作って「深入りしたい人だけどうぞ」にする。本編の流れを守るのが最優先。

  • 伏線と回収を設計する。序盤で投げた問い（例: 「当てはまるだけでは足りない」）を、 事例章で回収する。教科書に物語の背骨が通る。

Phase 2 — 章ごとに書く（V-S-V / Phase 1→2）

1 章 = 1 パーシャル（_NN-title.qmd）。本テンプレの 2 つの流儀を使い分ける。

  • 忠実翻訳 → 解説拡充（textbook_template.qmd）: まず定義・定理・式番号を省略禁止で 忠実訳（Phase 1）、その上に直観・図解・行間補完を重ねる（Phase 2）。
  • V-S-V（theory_template.qmd）: Visual（直観・図）→ Symbolic（数式）→ Verify（例・クイズ）の順。 数式が主役の章向き。

パーシャル統合: 章本文は _NN-*.qmd に分割し、{{< include >}} で本に統合する （single source of truth の運用は AGENTS.md を参照）。

Phase 3 — 対話デモ（効く所だけ）

「スライダーを動かすと分かる」箇所だけを Quarto Live 化する（原則 6 のうち 5）。 手順・落とし穴は Quarto Live レシピ と AGENTS.md に集約済みなので必ず先に読む。要点だけ:

  • 追加パッケージは親 qmd の YAML pyodide.packages で宣言（セル内 micropip.install は禁止）。
  • 日本語フォントは描画セル先頭で pyfetch→addfont（別セルにしない）。
  • font.family を日本語にすると mathtext の $\sqrt{}$ が豆腐化する → mathtext.fontset="cm" を入れ、 ラベルの \sqrt{X} は (X)^{1/2} に書き換える（Pyodide の matplotlib は根号中身を描けない）。

Phase 4 — 検証と公開

  • just check で品質確認、just docs（http://localhost:4312）でプレビュー。
  • 図・式・数値を原著と突き合わせる（原則 6）。特に数値と式番号は 1 つずつ照合。
  • GitHub Pages へ公開（CI は .github/workflows/publish.yml）。

3. 大事なこと（詳細な設計判断）

工程には現れにくいが、質を分ける判断。

  • 引用は最小・訳は主。原文は疑ったとき用の錨として畳んでおき、読者が読むのは忠実訳。 「原文の壁」を作らない。
  • 忠実訳 ≠ 逐語訳。数式・記号・固有名詞（KeYmaera X, BARON, Kepler …）は原形、 散文は自然な日本語に。訳し崩さず、日本語として読めること。
  • 行間補完の作法: (a) 論文が暗黙に使う定義を {#def-} で明示化する、
    1. 紛らわしい記号は対応表にする、(c) 数式の前に直観 callout、
    2. 「なぜ必要か」「どこで効くか」を前後章の相互参照で示す。
  • 通し例は徹底して使い回す。新概念 → 必ず通し例で具体化 → 抽象へ戻す。
  • 誠実な限界を 1 章置く。仮定・スケール限界・再現に要る商用ソルバ等を隠さない。 その後の発展（続く論文・系譜）を添えると「次に読む 1 本」に自然につながる。
  • 表は画像でなく実 Markdown 表にして #tbl- を付ける（画像は #fig-）。検索・引用・改訂に効く。
  • ライセンスを尊重。CC BY 等なら出典明記で翻訳・図の再掲が可能。出典行を機械的に全図へ。

4. よくある落とし穴（実際に踏んだもの）

症状 原因 対処
対話章が何も描画しない 親 qmd の YAML に pyodide.packages 未宣言で import 失敗 pyodide.packages: [numpy, matplotlib, …] を親に宣言（Quarto Live レシピ）
数式ラベルの根号が黒箱（豆腐） 日本語 font.family で mathtext が壊れる mathtext.fontset="cm" ＋ \sqrt{X}→(X)^{1/2}
図がぼやける／文字が読めない 低解像度のまま貼付 pdftoppm / magick で高 dpi クロップ、PNG を Read で視認してから貼る
式番号・図配置がズレる text＋LaTeX だけで qmd 化した extract-pdf の PNG を 1 枚ずつ Read（AGENTS.md の必須レビュー）
出典が抜ける 図を貼る時に出典行を忘れる 図キャプションのテンプレに 出典: …, CC BY 4.0 [@key] を最初から入れておく
本編が難所で止まる 完全性・重い証明を本文に置いた 付録へ隔離し、本文からは 1 行＋@sec-appendix 参照だけ

  | 第 III 部 考察 | 08 Discussion | Discussion |

  | 第 V 部 付録 | 13 付録 | 難所の隔離先 |

- **通し具体例を 1 つ選ぶ**（AI-Descartes では Kepler の第三法則）。抽象概念を導入するたびに、
  この例で必ず着地させる。全章で使い回す。
- **難所は付録へ隔離する**。完全性・Gödel・重い証明など、本筋を止める話題は本編から追い出し、
  付録に 1 節作って「深入りしたい人だけどうぞ」にする。本編の流れを守るのが最優先。
- **伏線と回収を設計する**。序盤で投げた問い（例: 「当てはまるだけでは足りない」）を、
  事例章で回収する。教科書に物語の背骨が通る。

### Phase 2 — 章ごとに書く（V-S-V / Phase 1→2）

1 章 = 1 パーシャル（`_NN-title.qmd`）。本テンプレの 2 つの流儀を使い分ける。

- **忠実翻訳 → 解説拡充**（`textbook_template.qmd`）: まず定義・定理・式番号を**省略禁止**で
  忠実訳（Phase 1）、その上に直観・図解・行間補完を重ねる（Phase 2）。
- **V-S-V**（`theory_template.qmd`）: Visual（直観・図）→ Symbolic（数式）→ Verify（例・クイズ）の順。
  数式が主役の章向き。

> パーシャル統合: 章本文は `_NN-*.qmd` に分割し、`{{< include >}}` で本に統合する
> （single source of truth の運用は AGENTS.md を参照）。

### Phase 3 — 対話デモ（効く所だけ）

「スライダーを動かすと分かる」箇所だけを Quarto Live 化する（原則 6 のうち 5）。
**手順・落とし穴は [Quarto Live レシピ](quarto-live.qmd) と `AGENTS.md` に集約済み**なので必ず先に読む。要点だけ:

- 追加パッケージは**親 qmd の YAML `pyodide.packages`** で宣言（セル内 `micropip.install` は禁止）。
- 日本語フォントは描画セル先頭で `pyfetch`→`addfont`（別セルにしない）。
- **`font.family` を日本語にすると mathtext の `$\sqrt{}$` が豆腐化する** → `mathtext.fontset="cm"` を入れ、
  ラベルの `\sqrt{X}` は `(X)^{1/2}` に書き換える（Pyodide の matplotlib は根号中身を描けない）。

### Phase 4 — 検証と公開

- `just check` で品質確認、`just docs`（`http://localhost:4312`）でプレビュー。
- **図・式・数値を原著と突き合わせる**（原則 6）。特に数値と式番号は 1 つずつ照合。
- GitHub Pages へ公開（CI は `.github/workflows/publish.yml`）。

## 3. 大事なこと（詳細な設計判断）

工程には現れにくいが、質を分ける判断。

- **引用は最小・訳は主**。原文は疑ったとき用の錨として畳んでおき、読者が読むのは忠実訳。
  「原文の壁」を作らない。
- **忠実訳 ≠ 逐語訳**。数式・記号・固有名詞（`KeYmaera X`, `BARON`, `Kepler` …）は原形、
  散文は自然な日本語に。訳し崩さず、日本語として読めること。
- **行間補完の作法**: (a) 論文が暗黙に使う定義を `{#def-}` で**明示化**する、
  (b) 紛らわしい記号は**対応表**にする、(c) 数式の前に**直観 callout**、
  (d) 「なぜ必要か」「どこで効くか」を**前後章の相互参照**で示す。
- **通し例は徹底して使い回す**。新概念 → 必ず通し例で具体化 → 抽象へ戻す。
- **誠実な限界を 1 章**置く。仮定・スケール限界・再現に要る商用ソルバ等を隠さない。
  その後の発展（続く論文・系譜）を添えると「次に読む 1 本」に自然につながる。
- **表は画像でなく実 Markdown 表**にして `#tbl-` を付ける（画像は `#fig-`）。検索・引用・改訂に効く。
- **ライセンスを尊重**。CC BY 等なら出典明記で翻訳・図の再掲が可能。出典行を機械的に全図へ。

## 4. よくある落とし穴（実際に踏んだもの）

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 対話章が何も描画しない | 親 qmd の YAML に `pyodide.packages` 未宣言で import 失敗 | `pyodide.packages: [numpy, matplotlib, …]` を親に宣言（[Quarto Live レシピ](quarto-live.qmd)） |
| 数式ラベルの根号が黒箱（豆腐） | 日本語 `font.family` で mathtext が壊れる | `mathtext.fontset="cm"` ＋ `\sqrt{X}`→`(X)^{1/2}` |
| 図がぼやける／文字が読めない | 低解像度のまま貼付 | pdftoppm / magick で高 dpi クロップ、PNG を Read で視認してから貼る |
| 式番号・図配置がズレる | text＋LaTeX だけで qmd 化した | `extract-pdf` の PNG を 1 枚ずつ Read（AGENTS.md の必須レビュー） |
| 出典が抜ける | 図を貼る時に出典行を忘れる | 図キャプションのテンプレに `出典: …, CC BY 4.0 [@key]` を最初から入れておく |
| 本編が難所で止まる | 完全性・重い証明を本文に置いた | 付録へ隔離し、本文からは 1 行＋`@sec-appendix` 参照だけ |
